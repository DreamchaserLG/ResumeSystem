# 企业内部简历筛选系统 · v1

FastAPI、Vue 3、PostgreSQL 16、Redis 7 和 Celery。PDF、Word、图片在本地解析；扫描件使用 PaddleOCR。字段抽取使用规则和词典，搜索使用 SQL、关键词与同义词，结果提供原文证据。淘汰由 HR 确认并留痕。

## 启动

```bash
mkdir -p storage
docker compose up -d --build
docker compose ps
```

前端：<http://127.0.0.1:5173>。API：<http://127.0.0.1:8001/api/docs>。Compose 先运行 SQL 迁移，再启动 API、worker 和前端。现有部署可在备份后使用原数据库和私有存储启动；旧解析记录可在申请详情中重新解析，发布后即可使用字段筛选。

本地演示账号：部门 HR 为 `hr.tech@company.internal`（`hr123456`），超管为 `admin@company.internal`（`admin123`）。接入公司数据前，更换示例密码与数据库凭据、禁用示例账号，并将接口部署在公司内网。worker 运行用户需对 storage 有写权限；OCR 模型可预置在 worker 的 `/home/resume/.paddlex`（离线部署先准备模型权重）。

## 使用顺序

1. 超管设置部门、HR 授权和字段策略；集成方按岗位及字段白名单单独授权。
2. 部门 HR 在岗位管理创建岗位并设置面试轮次。点击岗位的简历数量可进入该岗位的简历列表，从简历管理选择 PDF、Word 或图片导入。已知是同一候选人时，可以填写一条有权访问的申请编号建立关联。
3. 解析完成后，简历卡默认随窗口分页，也可自定义每页 1–100 份。点击标签可叠加筛选；点击卡片在右侧查看按原排版生成的脱敏分页预览，点击头像可放大。打开申请详情核对原文证据。在复核队列处理低置信、冲突和未登记字段。更正发布新版本。
4. 在候选人检索选择结构化条件、关键词或混合条件。证据不足进入待核实；HR 可直接在简历列表或详情更新招聘状态：待审核、推进中、淘汰、录取。推进中可选择岗位配置的轮次；若设「终面」，它必须在最后。使用「调剂」把申请移到另一个开放岗位，申请进入目标岗位的待审核状态，简历版本与原投递岗位保留。

[实施与验证说明](docs/V1-实施验收.md) · [外部 API 契约](docs/M7-外部API验收.md)

性别、详细地址、手机号和真实头像默认隐藏。超管可在系统设置逐项授权 HR 展示；性别、详细地址和头像需在授权后重新解析已有简历，且始终不参与筛选或导出。简历列表支持叠加岗位、招聘状态与院校标签；候选人检索页的正式院校筛选仍需逐岗位授权。简历卡只显示最高已核实学历；教育明细保留全部。学校按校名和别名映射，使用教育部 985、211、2022 第二轮双一流名单与 QS 2027 世界大学排名（含并列第 100）。有多所上榜院校时只显示最佳名次；点击名次或「QS 前 100」筛选，任何一所已核实院校上榜即匹配。国外院校通过目录匹配后显示「留学」；港澳台可显示 QS 名次，不标「留学」。未匹配的学校保留原文。旧版本的预览可通过重新解析生成多页预览。

技能采用一套「原文证据 → 词典中的标准技能 → 能力组」规则，适用于新导入和重解析的 PDF、Word 与图片。计算机技能中，PostgreSQL/MySQL/Redis 等归入「数据库」，Docker/Linux/Kubernetes 等归入「服务器部署」；人力资源和生物医药用同一机制映射到各自能力组。简历卡最多展示四项能力与一个主编程语言，明确标注优先，其次按编程语言列表顺序，再用工作或项目证据；没有编程语言证据则不显示。具体技能继续保留在结构化数据和原文证据里。能力组及别名可在词典迁移中维护，新增归组直接适用于已识别的技能，新增识别词需重新解析历史简历。

登录后点击右上角头像可查看和编辑个人资料。企业邮箱、角色和所属部门由管理员维护。已有部署需要应用迁移 `011_user_profile.sql`。

解析完成后，结构化字段和原文证据会写入 PostgreSQL。复核更正会保存为新版本，列表和检索使用新版本。重新解析时系统会保留可匹配的人工更正；无法安全匹配时，保留已核实版本并提示。原件不会因复核而修改。迁移 `012_review_and_preview.sql` 加入复核记录和预览版本字段；已有简历可重新解析来生成新版预览。

工作台按超管和部门 HR 展示招聘看板，支持悬停、键盘预览、全屏和下钻到「统计管理」。岗位管理可维护计划招聘人数与目标日期；未设置的开放岗位单列，缺口逐岗位按当前有效录取计算。期间趋势按北京时间计算，新增按原投递岗位、首次录取按当时岗位归属。超管接口只返回汇总，部门 HR 只看已授权的部门。现有部署需应用迁移 `016_recruitment_statistics.sql`。

首页招聘地图还需要迁移 `017_recruitment_atlas.sql`。可按地区 → 院校 → 专业下钻，并组合筛选院校标签、最高学历、时间、部门和岗位。地图以最高学历对应的院校所在地归类，院校标记是城市近似位置；公开底图及校园图来源见 [地图资料说明](frontend/public/maps/README.md)。性别统计限于明确披露且获准使用的值，缺失数据单列为「未披露」。
