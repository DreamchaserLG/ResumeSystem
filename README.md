# 企业内部简历筛选系统 · v1

FastAPI、Vue 3、PostgreSQL 16、Redis 7 和 Celery。PDF、Word、图片在本地解析；扫描件使用 PaddleOCR。字段抽取使用规则和词典，搜索使用 SQL、关键词与同义词，结果提供原文证据。淘汰由 HR 确认并留痕。

## 启动

```bash
mkdir -p storage
docker compose up -d --build
docker compose ps
```

前端：<http://127.0.0.1:5173>。API：<http://127.0.0.1:8001/api/docs>。Compose 先运行 SQL 迁移，再启动 API、worker 和前端。现有部署可在备份后使用原数据库和私有存储启动；旧解析记录可在简历管理的更多操作中重新解析，发布后即可使用字段筛选。

AI 分析的思考流可在服务端离线英译中：首次部署运行 `python scripts/setup_reasoning_translation.py` 下载并校验约 68 MB 的英译中模型，再重建 API 容器。模型文件只保存在本机 `models/translation/en_zh`，运行时由只读卷加载；前端通过 SSE 接收逐句译文。未安装模型时，界面显示中文提示，不展示未翻译的英文思考。

本地演示账号：部门 HR 为 `hr.tech@company.internal`（`hr123456`），超管为 `admin@company.internal`（`admin123`）。接入公司数据前，更换示例密码与数据库凭据、禁用示例账号，并将接口部署在公司内网。worker 运行用户需对 storage 有写权限；OCR 模型可预置在 worker 的 `/home/resume/.paddlex`（离线部署先准备模型权重）。

会话按浏览器标签页保存。刷新时向服务端验证会话，再重新加载当前页面；独立新开的标签页需要登录，可以使用另一个账号。右上角个人资料提供「在新标签页登录其他账号」。浏览器仍可自动填充账号和密码。同一账号的其他登录仍需要确认接管。

## 使用顺序

1. 在岗位管理维护岗位、招聘人数、目标日期和岗位描述。一个部门可设多个岗位；每个岗位仅能归属一个部门。超管可在左侧导航「用户管理」，或从岗位页面的部门行「账号」进入账号列表，创建部门 HR，账号创建即限定在该部门。超管可管理全部部门、岗位和简历。单份岗位说明可通过「导入岗位」上传 PDF、Word、图片或 TXT；建议用「岗位名称：」「所属部门：」「招聘人数：」「招聘类型：」「岗位职责：」等标签。导入仅提供草稿，请补齐、核对后保存。
2. 在简历管理选择招聘中的岗位，单份上传或通过文件夹批量导入 PDF、Word 和图片。查看逐文件解析状态，在候选人栏内直接筛选，可用滑块设置月薪和工龄范围。
3. 选中候选人可同时查看左侧的基本信息、跟进记录、结构化字段和右侧简历原文。在候选概览可生成岗位证据摘要。通过「写跟进」填写自由文本，最新备注会显示在候选人列表。面试安排和附件也会保留在跟进历史。
4. 在 AI 分析查看授权范围内的招聘统计与岗位证据，并下载报告。筛选到一个岗位后可按相关性排序，简历列表、分析表及下载报告不显示匹配分数。排序使用岗位要求和可核验的简历证据，HR 根据原文和面试记录做决定。

[实施与验证说明](docs/V1-实施验收.md) · [外部 API 契约](docs/M7-外部API验收.md)

性别、详细地址、手机号和真实头像默认隐藏。超管可通过现有管理接口逐项授权 HR 展示；性别、详细地址和头像需在授权后重新解析已有简历，且始终不参与筛选或导出。简历列表按授权的字段筛选，同类多选取任一命中，跨类取交集。简历卡只显示最高已核实学历；教育明细保留全部。学校按校名和别名映射，使用教育部 985、211、2022 第二轮双一流名单与 QS 2027 世界大学排名（含并列第 100）。有多所上榜院校时只显示最佳名次；选择「QS 前 100」筛选，任何一所已核实院校上榜即匹配。国外院校通过目录匹配后显示「留学」；港澳台可显示 QS 名次，不标「留学」。未匹配的学校保留原文。旧版本的预览可通过重新解析生成多页预览。

技能采用一套「原文证据 → 词典中的标准技能 → 能力组」规则，适用于新导入和重解析的 PDF、Word 与图片。计算机技能中，PostgreSQL/MySQL/Redis 等归入「数据库」，Docker/Linux/Kubernetes 等归入「服务器部署」；人力资源和生物医药用同一机制映射到各自能力组。系统保留能力组与主编程语言的归类结果。具体技能继续保留在结构化数据和原文证据里。能力组及别名可在词典迁移中维护，新增归组直接适用于已识别的技能，新增识别词需重新解析历史简历。

登录后点击右上角头像可查看和编辑个人资料。企业邮箱、角色和所属部门由管理员维护。已有部署需要应用迁移 `011_user_profile.sql`。

超管在「用户管理 → 管理」启用、停用或删除账号。停用使旧会话失效；删除清除登录资料和部门授权，保留历史跟进与审计。正在使用的超管账号无法停用或删除。已有部署需应用 `022_user_account_lifecycle.sql`。

解析完成后，结构化字段和原文证据会写入 PostgreSQL。复核更正会保存为新版本，列表和检索使用新版本。重新解析时系统会保留可匹配的人工更正；无法安全匹配时，保留已核实版本并提示。原件不会因复核而修改。迁移 `012_review_and_preview.sql` 加入复核记录和预览版本字段；已有简历可重新解析来生成新版预览。

招聘统计由 AI 分析展示。岗位管理可维护计划招聘人数与目标日期；未设置的开放岗位单列，缺口逐岗位按当前有效录取计算。期间趋势按北京时间计算，新增按原投递岗位、首次录取按当时岗位归属。超管接口只返回汇总，部门 HR 只看已授权的部门。现有部署需应用迁移 `016_recruitment_statistics.sql`。

旧版招聘地图的底图和院校数据来源见 [地图资料说明](frontend/public/maps/README.md)。

已有数据库需应用迁移 `018_recruiting_workspace.sql` 至 `020_recruiting_skill_dictionary.sql`。新增技能别名适用于后续导入与重解析。

查询分析以授权范围内的真实统计和已核实技能为依据，默认接入[阿里云百炼 GLM-5.3](https://help.aliyun.com/zh/model-studio/glm-5-3)。在项目根目录 `.env` 的 `DASHSCOPE_API_KEY=` 后填写控制台密钥，再执行 `docker compose up -d --no-deps api` 应用配置。国内（北京）端点和模型 ID 已预设；如使用工作空间专用端点，可设置 `RECRUITING_LLM_URL`。模型请求包含岗位需求或去身份的结构化汇总，不包含候选人姓名、联系方式或原始简历。留空或服务暂不可用时，页面显示本地规则总结。

同一账号只保留一个有效会话。登录成功时，Redis 为该账号保存唯一的会话指纹和有效期。若已有会话，服务端在校验密码后提示确认；只有确认当前那次会话后，才原子替换它。旧页面下一次请求、重新聚焦或定时校验时回到登录页。退出请求也比对会话指纹，旧页面无法注销新会话。

点击岗位名称进入候选人页，可查看岗位职责、任职要求及招聘来源，也可展开候选人的逐项原文证据。岗位管理支持按职能分类筛选。招聘网站参考稿供召回和人工复核使用。学历、年限和资质等条件由 HR 确认。

### 本地岗位与简历索引

PostgreSQL 16 服务带 pgvector。迁移 `028_resume_vector_retrieval.sql` 至 `030_reference_recruitment_configuration.sql` 增加岗位要求、经历切片、原文定位和参考排期。用工、实习和项目各以单条经历为父记录，512 token 以内整体编码，超长优先按原文条目拆分，条目内部的强制窗口保留 51 token 重叠。

岗位候选人页在授权部门、岗位和有效简历版本范围内计算得分，按总分从高到低分页。总分为职责分的 65% 加技能分的 35%。每项职责取允许范围内最相近的经历窗口，当前将 BGE-M3 的余弦值限制在 0 到 1 后用于职责试算。技能按词典或授权经历中的规范词项举证，必备权重 2、加分权重 1，待核实按 0 计。报告可从逐条要求跳到对应的完整脱敏经历，再打开对应的简历原页。同部门未关联的简历也可在岗位候选人页单独试算。

在具备本地 BGE-M3 权重、PyTorch、Transformers 和 Psycopg 3 的 Python 环境中运行以下命令。将 `DATABASE_URL` 设为目标库的迁移账号连接地址。导入公开参考稿时按部门和岗位名称匹配，数据库中已有人工编辑的内容会保留。

```bash
python -m migrations.migrate
python -m scripts.import_job_posting_references ../data/岗位参考JD-20261124.json
python -m scripts.backfill_retrieval --model-dir ../models/bge-m3
```

发布简历新版本或修改岗位后，可重跑索引命令增量更新。岗位配置可通过 `--export-jobs` 导出。对 HR 已确认的岗位要求，在对应快照的 `requirements` 中录入带 `kind` 和 `text` 的条目。可用类型包括 `duty`、`skill`、`degree` 和 `months`，后两种须填 `minimum`。用 `--approve` 导入确认配置并回填索引。

### 简历语义搜索与能力标签

简历管理和人才库共用语义搜索。姓名和岗位别名走授权字段检索，岗位语义查询和授权经历切片使用同一套本地 BGE-M3 向量。“人力”“HR”“HRBP”和“Human Resources”共享人力资源方向的召回。能力匹配取自然语言输入与能力词典的余弦相似度，保留 50% 及以上的结果，优先生成与最高分相差 10 个百分点以内的前三个标签。

在模型环境中启动常驻编码进程。Compose 的 API 通过 `./storage/embedding` 下的 Unix socket 调用进程，宿主运行账号需与容器应用账号（UID 1000）共享 socket 的组读写权限。

```bash
python -m scripts.embedding_server --socket ./storage/embedding/model.sock --model-dir ../models/bge-m3 --threads 2
```

使用以下命令监听简历发布和岗位变更，在事务提交后启动增量索引。每个已完成的批次即时写回。空闲时每三分钟补查一次，处理服务离线期间的变更。`DATABASE_URL` 使用迁移账号连接地址。

```bash
python -m scripts.backfill_retrieval --follow --model-dir ../models/bge-m3 --embedding-socket ./storage/embedding/model.sock
```

## 演示数据集

仓库只承载代码。演示数据（11 个部门、24 个岗位、403 份简历的原件、脱敏预览、结构化字段、原文证据，以及数据库快照）含真实候选人信息，按内部途径单独交付，不随仓库发布。

拿到数据包后，把它放回 `resume/`、`showcase/storage/` 和 `db/showcase.sql.gz` 三处，再执行 `make showcase` 即可载入并打开岗位与候选人。数据集构成、恢复方式与重建步骤见 [演示数据集](docs/演示数据集.md)。
