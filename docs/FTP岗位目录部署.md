# FTP 岗位目录与内网部署

## 目录与同步

Windows 文件服务器保管目录和简历。CentOS 定时读取目录和文件元数据，数据库记录目录、岗位和简历指纹。岗位管理读取数据库并提供手动同步。同步只下载相对上次成功同步新增和变更的简历。目录完整扫描及文件校验后再提交数据库变更。文件服务器删除源文件后，系统隐藏该来源创建的申请，保留申请历史。岗位目录消失时隐藏该来源创建的岗位，原有独立岗位保留。

- 根下可建分类目录，例如 `2026入职`。分类可继续嵌套。
- 岗位是子目录中的叶子目录。页面创建岗位时选择已存在的部门，并在 FTP 岗位目录写入部门标记。末级目录也可从 Windows 维护，导入时通过上层同名部门目录或 `部门-<ID>` 识别部门。普通空分类目录保留为文件夹。
- 岗位详情、流程和状态保存在系统中。外部岗位目录与已有岗位同部门且名称唯一匹配时复用已有岗位。
- 目录列表遵守部门权限。超级管理员可管理根目录和执行全局同步，部门招聘人员可在所属部门的目录中创建。
- 支持 PDF、DOC、DOCX、PNG、JPEG、WEBP，每份不超过 20 MB。向 FTP 投递时先用临时文件名写完，再重命名为正式文件名。
- 同步使用专用根目录和标记文件，防止连错目录时影响系统数据。解析任务仍使用现有简历处理队列。

## 发布与验收

本地先验证目录权限、叶子约束、增删改、不变文件零下载和读取异常时的回滚。GitHub 只发布源码和配置样例。CentOS 拉取已验证的提交，保留现有数据库、存储和环境配置。首次部署使用 Docker Compose 启动数据库、Redis、API、后台任务和 Nginx，Nginx 绑定指定内网地址。FTP 根目录、目录标记和实际简历通过独立的受限配置迁入 Windows 文件服务器。

上线检查包括局域网访问、登录、空目录和岗位创建、FTP 到数据库的首轮同步、重复同步、修改和删除、定时任务状态。回滚时停 FTP 调度，恢复上一版本容器和对应备份。

## CentOS 安装

1. 把服务配置写入服务器上权限为 `0600` 的 `.env`。参考 `.env.example` 设置数据库、FTP、存储与 `FRONTEND_BIND`、`FRONTEND_PORT`。原件缓存目录由容器用户 1000 写入。SELinux 启用时给共享缓存目录设置容器访问标签。如服务端支持 FTPS，使用默认的证书校验。
2. 在 FTP 上准备专用根目录，并用 `python -m scripts.seed_ftp_catalog 已分类目录 部门映射.json` 迁入源文件。映射的值为目标数据库现有部门编号。缺少部门的文件保留在待归类目录。同名已迁文件按内容核对，避免覆盖。
3. 新数据库先运行 `docker compose -f docker-compose.yml -f docker-compose.ftp.yml up -d pg redis migrate`，确认迁移完成后运行 `docker compose -f docker-compose.yml -f docker-compose.ftp.yml run --rm --no-deps api python -m scripts.init_lan_admin` 初始化内网管理员并禁用仍使用初始密码的演示账号。
4. 运行 `docker compose -f docker-compose.yml -f docker-compose.ftp.yml up -d --build` 启动服务。Nginx 对外提供网页并代理 API。最后从另一台局域网设备验证网页与登录。

用户可在简历管理的单份或批量导入中选择关联到 FTP 的招聘中岗位。文件按所选岗位写入 Windows，随后由后台同步和解析。
