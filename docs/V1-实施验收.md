## 验证与基线

在隔离的标准 PostgreSQL 16 和 Redis 7 上执行迁移和后端测试。常规测试与需 OCR 权重的图片测试可分别运行：

```bash
python -m migrations.migrate
python -m pytest -m 'not slow'
python -m pytest -m slow tests/test_parsing.py
```

自动化回归使用合成文件。若另有获准的真实图像集，可通过 `RESUME_OCR_EVAL_DATA` 指定数据目录，运行 `python -m eval.m3_report`。回归与评估使用隔离数据库，不要在生产库运行。

基线目录 [eval/baseline](../eval/baseline) 包含清单、合成语料、查询、标签和报告。用仅有迁移与种子的独立数据库复跑：

```bash
python -m eval.v1_baseline > eval/baseline/report.json
```

合成数据验证字段抽取、结构化/文本/混合召回、无结果查询、权限和原文证据。P@K 的分母是 K；返回少于 K 条时，空位会拉低 P@K。报告中的 SQL P95 是小样本重复查询的耗时观察，不是企业并发承诺。

实际投产验收仍需企业授权样本、双人标注的留出集、多版式 OCR 分层以及典型和最大授权范围的并发压测。后续如做向量实验，复用同批候选人、查询、相关性标注、K 和权限范围，单独存放实验结果。
