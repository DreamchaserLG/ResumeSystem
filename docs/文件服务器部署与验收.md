# 简历库共享目录部署

## 文件服务器与部门目录

使用内网 SMB（Windows 或 Samba）或 NFS 共享。文件管理员为各部门开设独立投递目录，目录名使用系统中的部门 ID，例如 `1/`、`2/`。各部门只向自己的目录投递，系统服务账号具有读取权限。文件名可以使用中文。读取支持 PDF、DOC、DOCX、PNG、JPEG、WEBP，单份上限 20 MB。

将共享挂载到运行 Docker Compose 的实体机，配置地址时使用挂载后的绝对路径。建议上传时先用临时扩展名，传完再重命名。扫描也会跳过最近 90 秒仍在变动的文件和符号链接。源文件由文件服务器保管，系统按部门与文件 SHA-256 去重。同部门同内容即使改名也只入库一次，内容不同的同名文件独立登记。

## 启动与检查

```bash
export RESUME_SHARE_DIR=/mnt/recruiting/resumes
export RESUME_DROP_HOUR=3
docker compose -f docker-compose.yml -f docker-compose.ingest.yml up -d --build
```

部署一套调度器。默认上海时间每天 03:00 扫描。常规 Compose 配置在未挂载共享目录时继续提供查询和人才管理。首次对接后可由运维触发一次扫描。

```bash
docker compose -f docker-compose.yml -f docker-compose.ingest.yml exec worker \
  celery -A worker.celery_app call worker.scan_resume_dropdir
docker compose -f docker-compose.yml -f docker-compose.ingest.yml logs -f worker resume-scheduler
```

解析成功的文件同步到系统私有文件存储，并在部门简历库中显示。文件无需对应岗位。上传文件的业务人员只需放到部门目录。解析失败的文件可在简历管理的更多操作中重新解析。格式校验失败可替换为修正后的文件，等待下一次扫描。系统不会移动或删除共享源文件。

验收时检查部门归属、原件与脱敏预览、重复投递和能力标签筛选。选择候选人放入人才库后，才可记录跟进状态和面试。数据库、私有预览和原件存储要一起备份。
