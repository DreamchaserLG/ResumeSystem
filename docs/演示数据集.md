## 一、直接恢复快照（最快）

需要一个已启动的 PostgreSQL。`restore` 会建库（不存在时）、跑迁移、再灌数据，最后核对 11 部门 / 24 岗位 / 403 投递。

```bash
# Docker 部署（仓库默认方式）
docker compose up -d --wait pg redis
POSTGRES_DB=resume_showcase STORAGE_DIR=./showcase/storage \
  docker compose run --rm --no-deps api python scripts/showcase_dataset.py restore
POSTGRES_DB=resume_showcase STORAGE_DIR=./showcase/storage docker compose up -d
```

```bash
# 本地 venv 直连（DATABASE_URL 指向本机 PG）
python scripts/showcase_dataset.py restore
```

只恢复不启动，也可以直接用 psql：

```bash
gunzip -c db/showcase.sql.gz | psql -d resume -v ON_ERROR_STOP=1
```

目标库必须先执行过 `python -m migrations.migrate`（快照只带数据，不带建表语句）。

## 二、从原始简历重建（可复现）

想验证导入链路而不是恢复快照时，用同一份映射文件重跑；UUID 由「文件夹 + 文件名」派生，重复执行不会产生重复投递。

```bash
python scripts/showcase_dataset.py audit     # 校验表格份数与文件份数逐项一致
python scripts/showcase_dataset.py prepare   # 建部门与岗位、写入 24 条岗位说明
python scripts/showcase_dataset.py import    # 逐份走上传接口解析入库（单进程，403 份）
python scripts/showcase_dataset.py verify    # 逐岗位核对份数与发布状态
```

`import` 走的是 UI 同一套上传接口，解析在进程内同步执行，跑完即可 `dump`。

## 三、重新导出快照

```bash
python scripts/showcase_dataset.py dump     # 生成 db/showcase.sql.gz
```

导出为 `COPY ... FROM stdin` 的纯 SQL，恢复时用 `SET session_replication_role = replica` 跳过外键顺序，并在结尾重置序列。

## 四、登录与数据说明

- 默认超管账号沿用种子数据：`admin@company.internal` / `admin123`，登录后请先改密码。
- 岗位页新增「简历来源文件夹」列，直接对应 `showcasePlan.json` 里的来源文件夹与份数。
- 简历原文、脱敏预览、结构化字段、原文证据（`resume_source_span`）都是真实解析结果；手机号、详细地址、性别、头像默认不展示。
- `resume/` 内的简历来自真实收集，文件名保留了原始姓名（未署名的是模板本身没填姓名）。仓库公开前请确认已获得投递人授权；若需完全脱敏，请把文件名改为 `未署名NNN-岗位` 并同步 `showcasePlan.json`，再用第二节的流程重建。
